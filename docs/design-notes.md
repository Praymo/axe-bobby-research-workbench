# 从原型到规则

## 两种时间尺度

研究证据变化慢，报价和入场条件变化快。如果把它们合成一个分数，很容易出现研究评分掩盖当下风险的情况。Python 版先处理研究和否决条件，再结合市场与入场状态，保留每一层原因。

## 页面不是 Python 的可视化接口

`demo/review-sandbox.html` 是原项目已有的早期交互原型，使用浏览器内置样例。它让阈值、否决原因和模拟通知可以被点出来看。

`workbench.py` 是后续公开整理的规则摘取。两者不共享参数和计算实现，不应拿页面分数验证 Python 输出。未来如果要合并，先统一输入和状态契约，再连接页面。

## 缺数据时怎么办

数据过期应当停止入场复核。整理时还检查了未来时间戳和非有限数值：错误时间不能被误认为特别新鲜，NaN 也不能穿过比较逻辑。这些边界由测试覆盖。

## 为什么保留离线输入

把行情获取和判定分开后，可以固定时间、报价和研究输入，重放同一个案例。公开版本因此能脱离真实账号运行。它验证的是规则行为，不代表真实数据链路已经验证。

## 后续如何验证

记录每次进入候选、被阻断和人工修改的原因，再比较限制条件的增量作用。还需要考虑交易成本、样本外稳定性和数据修订。这里没有把这些待做事项写成已取得的结果。
